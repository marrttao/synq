# PROGRESS


## Stage 13: easier to use
- Standard keys: `f` full screen, `*` favorite, F5 refresh, `{ }` layouts, `( )` palettes, Shift+arrows seek 30 s; every pair has a back key. Russian layout is mapped to the Latin keys (`keys::latin_for`).
- The list highlight follows the playing track; messages name the track; old messages give way to the key hint line.
- F10 / Ctrl+P menu with every tool and action and its key; scrolling help (`?`/F1).
- Layout editor redone: labelled boxes, mouse drag/resize (mouse captured only while editing), preset starts with 1-3, plain-language help. Letter keys no longer used.
- Color editor fixed: typing starts from an empty field (it used to be pre-filled and capped, so nothing could be typed); 3/6 hex digits, Left/Right shade.

## Stage 12: palettes of N colors
- `ui/palette.rs`: built-in sets and own palettes of 2..12 colors (`palette:<name>` in settings, current choice remembered and wins over config.toml). `T` cycles, `C` edits with live preview. Colors 6+ rotate with the accent on the current lyric line and panel titles (`Theme::rotating`).

## Stage 11: layouts and the layout editor
- `ui/layout.rs`: percent-based places for Library/Lyrics/Visual, player bar on/off; presets Classic (responsive), Lyrics, Cinema; custom layouts saved as `layout:<name>` in settings. `L` cycles, `E` edits (move, resize, scale, hide, save / save as new / delete).
- Known: the player bar is fixed at the bottom; panels may overlap if the user places them so; not tried in a real terminal.

## Stage 10: refresh, picture fill, ASCII, rebindable and global keys
- The picture is cover-cropped to the exact panel size (it fills 100%); first image in `gifs/` is shown until a choice is made, "(none)" is stored as "-".
- `v`: picture / ASCII (brightness ramp tinted with the pixel color); `visuals.mode` sets the default.
- `R`: rescans `music/` (library worker gets a refresh sender), resyncs playlists, drops and reloads pictures.
- `src/keys.rs`: 16 rebindable actions, chords, conflict and reserved-key checks, saved as `bind:<action>` in the settings table. `S` opens the settings window.
- `src/hotkeys.rs`: Windows RegisterHotKey thread; only Ctrl/Alt/F-key chords may be global. Registration and refusal tested; a real key press from another program was not verified here.
- Known: Linux has no global keys; `v` and `T` choices are not saved; media keys cannot be bound (terminals do not deliver them).

## Этап 8. Красота — выполнен

Сделано:

Длинная строка обрезается по ширине с «…». У строк без пословных меток — прежняя подсветка целой строки.

- **Темы**: `[theme] preset` = default / nord / gruvbox / light / mono; любые цвета из `[theme]` (`background`, `foreground`, `dim`, `accent`, `border`) по-прежнему переопределяют пресет — старый config.toml с явными цветами продолжает работать. Клавиша `T` переключает пресеты на лету (на следующий запуск не сохраняется — постоянный выбор в config.toml).
- **Справка `?`**: список всех клавиш (тест сверяет его с клавишами из ТЗ), закрывается любой клавишей.
- 11 новых тестов (разбор и обрезка караоке, пресеты и переопределения цветов, цикл тем, справка, полный экран на размерах до 1×1, подсветка слова на экране, эффекты включены / выключены). Всего 172 (+144 без фичи whisper), clippy `-D warnings` чист в обеих конфигурациях.

- Анимации и караоке проверены только в тестовом терминале (буфер), живого вида я не видел: длительности (350–500 мс) и цвета могут потребовать подстройки.
- Клавиша `T` не запоминает тему между запусками.

## Этап 7. Гифки — выполнен

Сделано:
- Зависимости: `image 0.25` (только gif / png / jpeg) и `ratatui-image 11.1` (без `chafa`, чтобы не требовать pkg-config; протоколы kitty / sixel / iTerm2 / halfblocks).
- `src/visuals/decode.rs` — разбор GIF / PNG / JPG в кадры один раз. Каждый кадр хранит собственную задержку из файла (задержки меньше 20 мс, как в браузерах, читаются как 100 мс). Кадры сразу уменьшаются до 360 px по длинной стороне (пропорции сохраняются), максимум 300 кадров, файлы больше 128 МБ отклоняются. Битый хвост GIF не мешает: берётся то, что успело разобраться.
- `src/visuals/mod.rs` — список картинок в `gifs/` (gif / png / jpg / jpeg без учёта регистра, скрытые пропускаются), фоновый поток (своё соединение с БД, отвечает только на последнюю загрузку), выбор сохраняется в `settings` (`gif_global`, `gif_playlist:<id>`), `Clock` — часы анимации: время идёт только когда ему его дают, поэтому пауза — это просто отсутствие вызовов. Имена файлов из настроек проверяются (никаких `..` и разделителей путей).
- Протокол: автоопределение запросом к терминалу (`Picker::from_query_stdio`), при неудаче — полублоки; `[visuals] protocol` принудительно задаёт kitty / sixel / iterm2 / halfblocks. Прозрачные пиксели рисуются поверх цвета фона темы.
- Панель «Visual» (справа, при ширине окна от 110): картинка масштабируется под панель с сохранением пропорций и по центру; под неё подгружаются кадры лениво. Без выбранной картинки — подсказка «Press g…», при ошибке — причина в панели и в строке состояния (повторно битый файл не загружается, пока его не выберут снова).
- Анимация ставится на паузу вместе с музыкой и когда ничего не играет (`[visuals] pause_with_music`, по умолчанию true).
- Клавиша `g`: окно выбора. Внутри плейлиста (или на его строке во вкладке Playlists) оно предлагает гифку этого плейлиста, `Tab` переключает на глобальную. «(none)» у плейлиста возвращает его к глобальной. Какой плейлист «играет сейчас», определяется тем, из какого списка запустили трек. Гифка удалённого плейлиста забывается (id в SQLite переиспользуются).
- Несколько раскодированных картинок держатся про запас, поэтому смена плейлиста не перечитывает файл.
- Тесты: 18 новых (декодер: задержки, масштаб, PNG, битые и пустые файлы; часы: задержки, обёртка, пауза; список файлов; безопасные имена; поток + сохранение выбора между запусками; UI: пустая папка, выбор → отрисовка полублоками → пауза и ход часов, плейлист против глобальной, ошибка загрузки, переключение Tab). Всего 161 (+133 без фичи whisper), clippy `-D warnings` чист в обеих конфигурациях.

Не сделано / известные проблемы:
- Реальный вывод через kitty / sixel / iTerm2 и запрос возможностей терминала я не мог проверить (в тестах — только полублоки). Если что-то не так, поставьте в `config.toml` `protocol = "halfblocks"` и сообщите, в каком терминале.
- Окно диалога поверх картинки в sixel-терминалах может оставлять артефакты.
- Файл картинки читается один раз за запуск: если подменить файл с тем же именем, нужен перезапуск.
- Узкое окно (меньше 110 колонок) прячет панель; режим «полный экран» с большой гифкой будет на этапе 8.

## Этап 6. Whisper — выполнен

Сделано:
- Cargo-фича `whisper` (включена по умолчанию): `whisper-rs 0.16` + `rubato` + `symphonia`. Без неё (`--no-default-features`) проект собирается, clippy чист и все прочие тесты проходят; запросы на распознавание просто игнорируются.
- `src/transcribe/audio.rs` — декодирование symphonia (mp3 / flac / ogg / wav / m4a / aac) → моно f32 → ресемплинг rubato (FFT) в 16 кГц. Битые пакеты пропускаются.
- `src/transcribe/engine.rs` — whisper.cpp: язык `auto` или из `[whisper] language`, таймстемпы токенов, `no_context`, подавление пустот и «не-речи», порог no-speech 0.6, потоков = половина ядер (музыка и UI не тормозят). Логи whisper.cpp идут через `log` → tracing → файл, а не в терминал. Если whisper.cpp не может открыть файл модели (на Windows это случается с очень длинными и не-ASCII путями, например с кириллицей в имени пользователя), модель читается в память и загружается из буфера.
- `src/transcribe/model.rs` — модели ggml с Hugging Face (tiny ≈ 75 МБ, base ≈ 142 МБ, small ≈ 466 МБ, medium ≈ 1.5 ГБ). Скачивание в `.part`, проверка сигнатуры файла (HTML-страница ошибки не принимается за модель) и размера, прогресс по процентам, при ошибке остатков не остаётся и уже имеющаяся модель не затирается.
- `src/transcribe/filter.rs` — фильтр «галлюцинаций» (с тестами): сегменты с no-speech > 0.6; аннотации `[MUSIC]`, `(applause)`, `♪♪`, `*sighs*`; типовые фразы-призраки («Thanks for watching», «Subtitles by …»); подряд идущие повторы (разрешено 2 подряд, 3-й и далее отбрасываются); короткие (≤ 2 с, ≤ 3 слов) обрывки, одиноко лежащие в тишине ≥ 10 с с обеих сторон. Токены собираются в слова, времена слов выравниваются (монотонность, границы сегмента).
- `src/transcribe/worker.rs` — фоновая очередь: текущий трек в приоритете, автоматические задачи для уже неактуальных треков пропускаются. Перед скачиванием модели UI спрашивает (`y` / `n`), показывает размер; отказ запоминается до явного нажатия `t`. Результат сохраняется как enhanced LRC в `data/lyrics/` (маркер `.nospeech`, если пения не нашлось, — повторно трек не распознаётся).
- Цепочка текстов: .lrc → теги → кеш → LRCLIB → Whisper. Автоматический запуск — если ничего не нашлось и трек играет уже 3 с. Включается и выключается в `[whisper] enabled`.
- UI: окно вопроса о загрузке модели, статус в нижней панели («whisper: downloading model 35%», «recognizing 42% (+1 queued)»), в панели текста — «No lyrics yet: recognizing 42%», по готовности текст появляется сам. `t` — распознать текущий трек заново (если Whisper выключен — повторить поиск онлайн).
- Проверено вручную на настоящей модели tiny (скачана с Hugging Face через `model::download`) на синтезированной речи: распознано за ≈ 2 с, получены строки со словами и таймстемпами, вывод разбирается парсером LRC. Повторить: `SYNQ_TEST_AUDIO=речь.wav cargo test real_model -- --ignored --nocapture`.
- 143 теста (+115 без фичи), clippy без предупреждений в обеих конфигурациях.

Что нужно для сборки с Whisper (пойдёт в README, этап 9):
- Windows: Visual Studio Build Tools (C++), CMake (есть в составе Visual Studio) и **libclang** (LLVM) — для bindgen. На этой машине LLVM-установщик требовал прав администратора, поэтому `libclang.dll` взят из официального пакета PyPI `libclang` и лежит вне проекта в `C:\Users\Sylvanas\.tools\libclang`; сборка идёт с `LIBCLANG_PATH` на эту папку и CMake из Visual Studio в `PATH`.
- Linux: `build-essential cmake libclang-dev` (+ `libasound2-dev` для звука).
- Заранее сгенерированные биндинги whisper-rs-sys собраны под Linux и на Windows не подходят, поэтому обходить bindgen нельзя.

Не сделано / известные проблемы:
- Распознавание пока не показывает прогресс в процентах для декодирования (только «decoding audio»); для очень длинных треков (часы) весь звук держится в памяти.
- Качество на пении с громкой музыкой у моделей tiny/base невысокое; для лучшего результата нужен `small` или `medium` в `config.toml`.
- Отменить уже запущенное распознавание нельзя (результат всё равно сохранится в кеш).
- Распознавание на GPU не включено (CPU).
- Живую работу в интерфейсе с настоящим пением не проверял.

## Этап 5. Тексты — выполнен

Сделано:
- `src/lyrics/lrc.rs` — парсер LRC: обычный и enhanced (`<mm:ss.xx>` по словам, закрывающий тег как конец строки), доли секунды из 1–3 знаков, несколько меток на строку, заголовки `[ar:]`/`[ti:]` пропускаются, `[offset:]` применяется ко всем временам (по соглашению LRC положительное значение — раньше), BOM и CRLF. Текст без меток возвращается как `Plain` (пустые строки между куплетами сохраняются). 16 тестов.
- Цепочка источников (`src/lyrics/mod.rs`): `<трек>.lrc` рядом → теги (USLT / LYRICS / ©lyr через lofty) → кеш `data/lyrics/` → LRCLIB (если `lyrics.online = true`). Whisper появится на этапе 6.
- `src/lyrics/lrclib.rs` — `GET /api/get` (artist_name, track_name, album_name, duration), свой User-Agent `synq/<версия>`, таймаут 5 с. Берётся `syncedLyrics`, иначе `plainLyrics`. Реальный формат ответа проверен живым запросом. Сетевые ошибки не мешают воспроизведению и не кешируются. Для «Unknown Artist» онлайн-поиск не делается.
- `src/lyrics/cache.rs` — кеш: `.lrc` (синхронный), `.txt` (простой), `.none` («не найдено» — LRCLIB не опрашивается повторно). Имя файла: читаемая часть + хеш FNV-1a относительного пути, запись атомарная.
- Сдвиг тайминга хранится в БД (`settings`, ключ по пути трека) и восстанавливается при следующем запуске.
- Отдельный поток; при быстром переключении треков отвечает только на последний запрос.
- UI (центральная панель): текущая строка по центру и выделена, соседние приглушены; до первой строки показываются ожидающие строки; длинные строки обрезаются «…»; простой текст — прокручиваемым блоком; заголовок панели показывает источник и сдвиг; состояния «Looking for lyrics...» / «No lyrics found» (+ причина при сбое сети). Позиция между отчётами аудиопотока (раз в 100 мс) досчитывается по часам — строки и прогресс-бар двигаются плавно.
- Клавиши: `l` — показать/скрыть текст, `[` / `]` — сдвиг ∓/±0.1 с (`]` = текст позже), `t` — повторить поиск (сбрасывает кеш «не найдено» и спрашивает LRCLIB снова), Ctrl+↑ / Ctrl+↓ — прокрутка простого текста.
- 112 тестов, в том числе: локальный HTTP-сервер для проверки запроса (параметры, User-Agent, 404, 500, недоступный сервер), запись и чтение тегов, сквозной сценарий UI (трек с .lrc → сдвиг → трек без текста → повтор → возврат). clippy без предупреждений.

Не сделано / известные проблемы:
- ID3 SYLT (синхронный текст в тегах) не читается: lofty его не поддерживает. USLT/LYRICS с LRC-текстом внутри работают.
- Клавиша `t` пока только повторяет поиск; на этапе 6 она же запустит распознавание Whisper.
- Если `.lrc` рядом с треком появился во время воспроизведения, он подхватится при следующем запуске трека.
- Анимация прокрутки и подсветка слов (караоке) — этап 8; данные по словам парсер уже отдаёт.
- reqwest использует rustls с aws-lc-rs: на Windows сборка прошла без доп. инструментов, но на чистой системе может понадобиться CMake/NASM (в README этапа 9 проверить).

  - создание / переименование (с переносом папки) / удаление плейлистов; имена проверяются (запрещённые символы Windows, зарезервированные имена CON/NUL/COM1…, точка в конце, длина), дубликаты ищутся без учёта регистра;
  - добавление трека создаёт хардлинк (`std::fs::hard_link`), при неудаче — обычная копия (без перезаписи существующих файлов); совпадение имён → суффикс « (2)», « (3)»…;
  - удаление трека из плейлиста / избранного удаляет только ссылку, файлы в `music/` не трогаются; удаление плейлиста удаляет только созданные им ссылки и пустую папку (чужие файлы в папке остаются);
  - проверка при старте: недостающие папки и ссылки досоздаются, лишнее не трогается и пишется в лог; для пропавших исходников ссылка не создаётся, запись в плейлисте остаётся;
  - фоновый поток со своим подключением к БД, UI получает снимки состояния по каналу.
- UI: вкладки Library / Playlists / Favorites, ★ у избранных треков, открытие плейлиста по Enter (Esc / Backspace — назад), всплывающие окна (имя плейлиста, подтверждение удаления, выбор плейлиста). Поиск `/` по исполнителю, названию и альбому (в Playlists — по названию плейлиста), Esc сбрасывает фильтр.
- Клавиши: `f` — избранное (выбранный трек, иначе играющий), `a` — добавить в плейлист, `c` — создать, `e` — переименовать, `d` / Delete — удалить плейлист (с подтверждением `y`) или убрать трек из плейлиста / избранного, `/` — поиск.
- 61 тест: имена, хардлинк (запись в оригинал видна в ссылке), суффиксы, переименование, удаление, синхронизация на временной папке, сценарий UI целиком (создать → избранное → добавить → поиск → убрать → удалить) и отрисовка всех режимов в окнах разного размера (вплоть до 1×1). clippy без предупреждений.

Не сделано / известные проблемы:
- Порядок треков в плейлисте — по порядку добавления; перестановки нет.
- Ссылки не пересоздаются на лету, если файл вернулся в `music/` — только при следующем запуске.
- Если у плейлиста вручную переименовать папку на диске, при запуске она будет создана заново, а старая останется как «неизвестная» (только запись в лог).
- Переименование только в регистре работает на Windows; на Linux проверить на этапе 9.
- Тест хардлинка требует ФС с поддержкой жёстких ссылок (NTFS, ext4, tmpfs — да; FAT — нет).

## Этап 3. Воспроизведение — выполнен

Сделано:
- `rodio 0.23` (без лишних фич: playback + mp3/flac/vorbis/mp4/wav, всё на symphonia).
- `src/audio/queue.rs` — очередь: порядок, shuffle (Fisher-Yates на собственном xorshift, без нового крейта), repeat off / all / one, next / prev. Текущий трек при включении/выключении shuffle не меняется; при обходе по кругу в shuffle первым не идёт только что игравший трек.
- `src/audio/mod.rs` — поток воспроизведения. Команды: Play, Pause, Resume, Seek, Next, Prev, Volume, SetShuffle, SetRepeat, Stop; события: Started, Position (каждые 100 мс), Paused, Stopped, Error. Автопереход к следующему треку делает сам поток (без задержки на UI). «Назад» после 3 с воспроизведения перематывает трек на начало. Нечитаемые файлы пропускаются с ошибкой в статусе; если нет звукового устройства, ошибка показывается один раз и воспроизведение останавливается.
- `src/ui/player.rs` — состояние плеера в UI, расчёт перемотки и громкости (с тестами).
- UI: нижняя панель с названием, прогресс-баром и временем, громкостью, shuffle/repeat; играющий трек в списке помечен ▶. Клавиши: Enter — играть выбранный (очередь = весь список без missing-файлов), Space — пауза (или старт выбранного), n / p, ← / → (шаг из `audio.seek_step_secs`), + / - (шаг 5%), s, r.
- 43 теста (включая реальный проигрыш двух WAV через устройство и пропуск битых файлов). clippy без предупреждений.

Не сделано / известные проблемы:
- Позиция обновляется раз в 100 мс; на очень быстром прогрессе полоса ходит чуть ступенчато.
- Перемотка зависит от формата: если rodio/symphonia не умеет seek для файла, в статусе будет «seek failed».
- Очередь — снимок списка на момент запуска; новые файлы из библиотеки в неё попадут при следующем запуске трека.
- Громкость не сохраняется между запусками (берётся из `config.toml`).
- Проверено только на Windows. На Linux понадобится ALSA dev-пакет (будет в README).

## Этап 2. Библиотека — выполнен

Сделано:
- `src/db.rs` — SQLite (rusqlite bundled, WAL), миграции через `PRAGMA user_version`, таблицы tracks / playlists / playlist_tracks / favorites / settings (последние три пока не используются). Путь трека хранится относительно `music/` с разделителем `/`. Слишком новая схема отклоняется.
- `src/library/tags.rs` — теги через lofty; название = имя файла, исполнитель = «Unknown Artist», если тегов нет.
- `src/library/scan.rs` — рекурсивный обход `music/` (симлинки на папки не обходятся), поддерживаются mp3 / flac / wav / ogg / m4a / aac. Изменения определяются по размеру + mtime. Новые и изменённые файлы перечитываются, исчезнувшие помечаются `missing` (строка и связи остаются), вернувшиеся снимают флаг. Нечитаемые файлы пропускаются и пишутся в лог один раз.
- `src/library/mod.rs` — фоновый поток со своим подключением к БД и `notify` (рекурсивно, дебаунс 500 мс), отправляет в UI полные снимки списка по каналу. UI не обращается к БД и диску.
- UI: левая панель с вкладками Library / Playlists / Favorites (две последние — заглушки), список «Исполнитель - Название  m:ss», недоступные файлы серые и зачёркнутые, навигация ↑/↓/j/k, PgUp/PgDn, Home/End, Tab / Shift+Tab; выбор сохраняется на том же треке при обновлении списка; в строке статуса число треков и «scanning...».
- 26 unit-тестов (в т.ч. сканирование на временной папке с настоящими WAV и живой тест watcher: файл появился → в списке, удалён → missing). clippy без предупреждений.

Не сделано / известные проблемы:
- Форматы m4a/aac/ogg проверены только по расширению и lofty, на реальных файлах вручную не пробовал; opus не поддерживается (symphonia его не декодирует).
- Если `music/` временно недоступна (например, отмонтирован диск), все треки получат `missing`; при возвращении папки флаг снимется сам.
- Первое сканирование очень большой библиотеки показывает список только после завершения (без промежуточных снимков).
- Watcher проверен только на Windows.
